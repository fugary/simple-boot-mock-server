# Simple Boot Mock Server 本地功能指南

本文随应用发布，依据仓库 README、MockTips 帮助页及其中英文使用指南整理。维护功能时应同步更新本文，避免将设计文档中未实现的能力作为现有功能。以下内容用于帮助问答，不包含用户的项目数据、接口配置、密钥或日志。

## 快速上手
1. 登录后打开“Mock管理 → Mock分组”，选择项目，也可以使用默认项目。新增分组并保存，分组路径可留空自动生成；手动填写时须全局唯一。
2. 进入该分组的请求列表，新增请求，方法选 GET，请求路径填 /hello。
3. 添加响应数据，状态码设为 200，内容类型选 JSON，粘贴以下内容并保存请求及响应：

```json
{"code":0,"message":"ok","data":{"id":1,"name":"Alice"}}
```

4. 打开请求测试并发送请求，预期得到上面的 JSON。复制页面提供的完整 Mock 地址，在浏览器或前端调用；只访问 /hello 不包含分组路径。
5. 接口正常返回后，再尝试失败响应、延迟、随机数据或代理。首次使用不需要脚本或 AI 配置。

## 请求测试与前端接入
请求测试支持 URL 参数、路径参数、请求头、请求体和认证配置，测试参数可保存复用。GET 示例可用浏览器访问，POST 等方法应使用请求测试或 HTTP 客户端发送，保持方法、路径和请求内容一致。JSON 请求体应使用 application/json。
完整 Mock URL 包含部署地址、/mock/、分组路径及请求路径，以页面复制的 URL 为准，不要猜测端口或部署前缀。前端可以替换单个接口 URL，或按实际请求路径设置分组基础地址。
测试结果可查看响应状态、头信息、正文及耗时，也可查看原始内容、结构化数据或使用可用的文件下载入口。代理测试得到合适结果后，可将代理响应保存为 Mock 数据。

## 项目、分组与代理
Simple Boot Mock Server 是 API Mock 服务。项目组织分组，分组中维护请求及其响应数据。分组可配置代理地址，只 Mock 指定请求，其余请求转发到真实后端。请求支持 URL 路径和 HTTP Method 匹配，也可通过匹配表达式根据请求内容区分请求。不能仅凭用户描述推断其实际分组配置或匹配结果，应引导其查看诊断。

## 暂停 Mock
代理地址支持 HTTP/HTTPS。临时需要真实响应时可暂停请求或响应数据的 Mock，完成后恢复；有代理则访问代理，没有代理则返回 404。暂停与删除不同。若返回来源不符合预期，查看诊断中的 Mock 返回、代理返回或未匹配信息。

## 响应配置与版本历史
同一个请求可维护成功、业务失败、空列表等多条响应，最简单的切换方式是将需要的响应设为默认。需要按参数区分时再配置匹配表达式；没有匹配规则且存在多条响应时可选择自动、随机或轮询策略。
响应可配置状态码、响应头、内容类型、字符集和延迟（毫秒）。例如 1000 毫秒可模拟慢接口。业务失败 JSON 不一定是 HTTP 错误，模拟 HTTP 错误时还要修改状态码。支持 JSON、XML、HTML 等内容；重定向可设置状态码 302 并在响应中配置目标 URL。
响应修改会记录历史，可以查看变更、比较版本和恢复旧版本。恢复会以旧版本内容作为最新数据，执行前应检查差异。

## 变量替换与 Mock 变量
固定响应也能回显参数。例如调用 URL 带有 ?id=123，响应填写：

```json
{"id":"{{request.parameters.id}}"}
```

这里回显的是字符串。需要保留数字、对象等类型时，可使用 JavaScript 自执行函数返回对象。路径参数读取 request.pathParameters，合并参数读取 request.params。先通过请求测试确认参数来源和值。
分组提供“Mock变量”名称和值的配置入口。在请求测试的参数中可使用 {{变量名}} 引用已启用变量，例如配置 token 后，在支持变量替换的字段中填写 {{token}}；这是测试端的参数替换，不是脚本中的全局变量。编辑器的 Mock 字典提供日期、名称、地址、图片等 MockJS 占位符和函数提示，选择插入后可调整。MockJS 占位符、分组变量与 request 请求参数是不同概念。

## 基础响应与 MockJS
响应可以填写静态 JSON，也可使用 JavaScript 和 Mock.mock(data) 生成数据。基础示例：
```javascript
Mock.mock({
  'data|10': [{ id: '@integer(1, 10000)', name: '@name', birthday: '@date' }]
})
```
脚本可用立即执行函数返回结果：
```javascript
(function () {
  return { id: request.params.id, body: request.body };
}())
```
帮助页的基础示例、内置对象、内置函数及后置处理页提供可复制示例，复制后按实际接口调整。

## 请求对象与匹配
request.body 是请求体对象；request.bodyStr 是请求体字符串；request.headers 是请求头对象；request.parameters 是请求参数；request.pathParameters 是路径参数；request.params 合并请求参数和路径参数。还可读取 request.ip、request.userAgent、request.cookies。
匹配表达式根据 request 内容返回匹配结果，支持表达式测试。需要区分相同路径的不同请求时，可结合 Method 和表达式检查参数、请求头或请求体。不要猜测未提供的匹配优先级。

## 响应与后置处理
response.statusCode 是状态码；response.headers 是响应头；response.body 是响应体对象；response.bodyStr 是响应体字符串。后置处理可修改状态码和响应头并返回新响应体，例如：
```javascript
(function () {
  response.statusCode = 200;
  response.headers['Content-Type'] = 'application/json';
  return xml2Json(response.bodyStr);
}())
```

## 异步请求与模块
脚本支持 fetch(url, options) 和 async/await：
```javascript
(async function () {
  const response = await fetch('https://httpbin.org/put', {
    method: 'put', body: JSON.stringify({ username: 'example' })
  });
  return await response.json();
}())
```
require(url, options) 是异步 CommonJS 风格模块加载，返回 Promise，使用 await require(...)。支持 module.exports 和 exports，不支持 ESM export/import。默认按 URL 缓存模块，帮助页列有 clearRequireCache 缓存清理函数。不要把完整 Node.js 运行环境或 npm 包自动安装能力视为本项目能力。

## 内置工具与加解密
内置 Mock.mock、dayjs、xml2Json(xmlStr)、json2Xml(jsonStr, rootName)、encodeHex、decodeHex、btoa、atob。提供 md5Hex/md5Base64、sha1Hex/sha1Base64、sha256Hex/sha256Base64；encryptAES/decryptAES、encryptDES/decryptDES、encrypt3DES/decrypt3DES、encryptSM4/decryptSM4、encryptRSA/decryptRSA，以及 signRSA/verifyRSA。加密调用接受 data、key、options，具体算法选项须以本项目帮助示例和实现为准；本文未列出默认模式和填充，不应猜测。

## 请求诊断
在请求测试结果或请求日志中打开诊断，查看流程及明细，定位分组、场景、请求匹配、响应选择和后置处理等阶段的问题。轮询分组的计算结果和回退原因也可在诊断中查看。助手不能自行读取这些日志，用户需提供必要的脱敏信息。

## 响应轮询
将响应选择方式设为轮询，可依次返回候选响应。轮询分组留空时接口共用进度；填写 request.params.orderId 或 request.body.pnr 等表达式后，不同结果分别计数。表达式必须返回非空字符串或有限数字，无效值或求值失败回退到接口共用进度。

## Schema 与复杂参数
测试请求时，在支持对象编辑的参数行点击“编辑对象参数”，按结构编辑复杂参数。请求关联 Schema 时，可查看结构并使用可用的示例生成入口；响应编辑器也支持依据响应 Schema 生成示例。生成后先检查，再发送或保存。

## 场景与置顶
在分组的场景管理中维护场景，为请求指定所属场景，再切换分组当前场景进行联调。请求列表中的场景筛选用于查看对应请求。项目、分组、请求支持通过星标或置顶操作排列常用记录。

## 导入
在分组列表打开导入，选择目标项目并上传文件。支持本系统导出格式、HAR（HTTP Archive 1.2）、Swagger/OpenAPI、Postman 和 FastMock 格式。选择文件后会尝试识别格式，出现类型冲突时核对并切换到识别结果。单文件和总大小限制以导入窗口显示的实际配置为准，不能猜测固定限制。

## 导出与复制
分组列表支持导出全部或选中数据，用于备份和迁移；导出前确认项目与选中范围。导入本系统导出文件可迁移 Mock 配置。分组与请求提供复制到目标位置的入口，复制后检查路径、代理、场景及响应配置。
Swagger/OpenAPI 导入可选择合并为单个组，关闭后按 tags 分组。导入后应检查方法、路径、响应样例和 Schema，再发送请求验证；导入成功不代表远端认证与业务逻辑完整可用。

## 流式与文件响应
支持 text/event-stream 类型的 SSE 响应。正文可为数组或含 stream 数组的对象，数组项可使用 data 承载内容、delay 指定发送该项前等待的毫秒数，例如：

```json
{"stream":[{"data":"hello","delay":200},{"data":"world","delay":200}]}
```

配置相应流式内容类型后，用支持 SSE 的客户端验证。示例在发送完数组后结束，不代表无限订阅；SSE 后置处理逐项执行。
脚本可用 fetch 获取文件并返回 await response.blob()。测试图片、音频、视频或其他流响应时，按类型设置 Accept 为 image/*、audio/*、video/* 或 application/*，并按页面提示下载或预览文本。

## 用户与管理工具
- 项目组织分组，提供公开项目入口和项目用户管理。普通用户管理有权访问的数据，管理员可查看其他用户数据；可编辑范围以实际权限为准，不能仅凭公开列表推断可修改。
- 用户管理维护账号，个人信息支持修改密码。帮助 AI 不会自动读取账号或权限配置。
- 数据看板展示调用趋势、项目分布、返回类型、高频接口、活跃用户和贡献情况；我的数据与全部数据的可用范围取决于权限。
- Mock 请求日志用于检查调用和诊断，系统日志管理用于查看系统操作等日志，AI 日志用于查看 AI 调用。
- 管理员可在定时任务页查看任务和执行记录，并手动触发可执行任务。Mock 日志清理按保留天数执行，保留配置未启用时跳过，不能假定固定保留天数。
- 管理入口包括对象池管理和 H2 数据库，实际可用性取决于权限及部署。支持 H2 与 MySQL，Java 运行基线为 JDK 11。
- 常用工具提供代码编辑器、对比编辑器、图标管理和查看帮助。界面支持中英文、明暗主题。

## 常见问题
| 现象 | 优先检查 |
| --- | --- |
| 404 或未匹配 | 完整 Mock URL、分组路径、方法、请求路径、启用或暂停状态、当前场景、匹配条件和代理配置 |
| 返回真实后端内容 | 诊断中的代理阶段，Mock 是否暂停，请求及响应是否匹配 |
| 总返回同一份数据 | 默认响应、候选响应、匹配规则、响应策略及轮询分组表达式 |
| request.body 字段取不到 | JSON 内容及 Content-Type；非 JSON 内容可检查 request.bodyStr |
| 修改后仍是旧内容 | 是否保存了当前响应，是否调用正确分组、场景和默认响应 |
| 格式或类型不符 | 状态码、Content-Type、字符集、脚本返回值及后置处理；字符串替换不等于类型转换 |
| 导入失败 | 文件格式是否与选择一致，结构和大小是否符合窗口要求，具体错误信息 |
| AI 提问入口不可用 | 当前用户是否有启用且默认的 AI 配置，先测试配置，再查 AI 日志 |

排错时提供脱敏的方法、路径、必要参数、预期及实际结果和诊断信息。AI 无法自动读取项目数据，也不能确认文档未描述的能力。

## AI 配置、日志与帮助提问
在系统管理的 AI 配置中添加 OpenAI 兼容、Anthropic 或 Gemini 配置，填写接口地址、密钥和模型。OpenAI 和 Anthropic 地址通常包含 /v1，Gemini 通常包含 /v1beta。模型支持刷新加载或手填；保存后可测试提示词。测试时临时选用的模型只影响本次调用。
编辑时仅在供应商和接口地址未变更时可将密钥留空保留原值，变更供应商或地址需重新填写密钥。AI 日志支持按配置、关键词、状态筛选及查看请求、响应、错误详情和删除。
帮助页的 AI 提问使用当前登录用户已启用且设为默认的 AI 配置及其默认模型，没有该配置时需先设置。每次提问独立，不包含之前的问答。后端把本指南和当前问题发送给配置的 AI 服务，调用记录进入现有 AI 日志。不会自动读取或发送用户的 Mock 数据。回答应引用本文章节；本文没有覆盖的功能应明确告知无法确认。生成的示例需检查后再使用。
